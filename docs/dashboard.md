# Dashboard 使用说明

[简体中文](dashboard.md) | [English](dashboard.en.md) | [日本語](dashboard.ja.md)

## 直接启动

需要 Windows x64 和 .NET 10 Desktop Runtime（安装 .NET 10 SDK 也已包含运行环境）。先发布：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\publish-dashboard.ps1
```

发布完成后双击：

```text
artifacts\inputd-dashboard-win-x64\inputd-dashboard.exe
```

程序会请求管理员权限并显示一次 UAC 提示。需要录制以管理员权限运行的游戏时必须允许，否则 Windows 会在游戏获得前台焦点后停止向普通权限的后台录制器投递 Raw Input；表现就是游戏可以操作，但 Dashboard 计数和 JSONL 同时停住。

不要只复制这个 EXE；当前发布方式依赖同目录的 DLL 和运行时配置文件。整个 `inputd-dashboard-win-x64` 目录应一起保留。

也可以从源码启动：

```powershell
dotnet run --project src/InputExecutor.Dashboard -c Release
```

## 界面功能

- 白色键盘实时显示当前按键；按下的键变为黑色，释放后恢复白色。
- 鼠标图显示左键、右键、中键状态，以及最近一次相对移动方向、`ΔX/ΔY`、滚轮和屏幕位置。
- `启动 inputd` 启动同目录的独立后台服务；若服务已经运行，状态卡会显示“运行中”。
- `开始录制` 创建 JSONL 文件并开始写入示范轨迹。
- `停止录制` 刷新写入队列并安全关闭当前文件。
- `打开录制目录` 打开输出文件夹。
- `生成训练数据` 将完整的事件级 JSONL 转换为 20/40/60Hz 或 1–1000Hz 自定义频率的训练帧，并生成 SHA-256 完整性清单。
- `快捷键设置` 修改全局开始/停止录制快捷键；即使焦点在游戏内也能触发。
- `选择操作记录` 校验并选择事件级 `human_raw_input` JSONL；序号断档、时间倒退、未知按键或损坏 JSON 会在注入前被拒绝。
- `播放操作` 按记录中的原始相对时间、held 键、held 鼠标按钮、相对鼠标增量和滚轮值重新执行。
- `停止播放` 取消回放并立即释放回放按住的全部键与鼠标按钮。
- `清空状态` 清空界面计数和最近事件显示，不删除已经录制的文件。

Dashboard 会在未录制时记住最近获得焦点的外部窗口，并在状态栏显示“目标”。正常流程是先让游戏获得一次焦点，再切回 Dashboard 开始录制；该游戏窗口的 HWND、PID、进程路径和标题会写进轨迹。录制开始后目标固定，不会因为切回 Dashboard 停止录制而被替换。

默认输出目录：

```text
%USERPROFILE%\Documents\inputd-recordings
```

可在启动前通过 `INPUTD_DASHBOARD_RECORDING_DIR` 指定其他目录。

## 全局录制与回放快捷键

默认快捷键：

- `Ctrl + Alt + F9`：开始录制；
- `Ctrl + Alt + F10`：停止录制；
- `Ctrl + Alt + F7`：播放已选择的操作记录；
- `Ctrl + Alt + F8`：停止播放。

点击“快捷键设置”，再点击对应输入框并直接按下新组合键即可修改。设置保存在：

```text
%LOCALAPPDATA%\inputd\dashboard.settings.json
```

快捷键通过 Windows `RegisterHotKey` 注册，不安装低级键盘 Hook。程序会检查四个快捷键重复、修饰键无主键、系统占用和注册冲突；`Ctrl + Alt + F12` 固定保留给 inputd 紧急停止。

为了训练数据边界完整，开始操作会等待快捷键全部释放且 Raw Input 消息队列稳定后才创建录制上下文；停止操作也会等待主键与修饰键全部释放后再停止和 Flush。停止后程序对已完成文件做流式、同目录原子重写，只清除本次开始/停止录制快捷键的物理代码和 held 状态，不删除事件行、鼠标位移或其他按键。原始事件在此之前仍然照常 WriteThrough 落盘；重写失败会保留原文件，不会为了过滤快捷键而把最近数据只放在内存中。

回放不会使用一次一个 HTTP 请求。播放器逐条读取轨迹并等待独立 `InputScheduler` 的单线程执行结果，因此相邻的鼠标增量不会被 latest-wins 覆盖。高轮询率鼠标通常连续产生大量 `±1` Raw Input count；Windows 会把单独发送的微小 `SendInput` 位移按指针速度舍入为零。播放器会把 held 状态相同、相距不超过 2ms 的相邻鼠标包合成一次注入，严格保留窗口内 `dx/dy/wheel` 的有符号总和，不修改源训练文件。选择文件和回放完成时日志都会显示源鼠标事件数及累计 `ΔX/ΔY`。

回放栏的“内核鼠标兼容”默认不勾选。默认模式在与 Dashboard 相同的管理员完整性级别运行：相对镜头移动使用 Win32 `mouse_event`，扫描码键盘、鼠标按钮、滚轮、绝对坐标和文本仍使用 `SendInput`。该模式不需要安装驱动，但仍需在离线或目标明确允许的环境中自行验证兼容性。

只有另一个特定游戏在同等权限下仍拒绝默认相对鼠标时，才考虑勾选“内核鼠标兼容”。它把相对移动、鼠标按钮和滚轮交给可选鼠标类驱动；扫描码键盘、Unicode 文本和桌面绝对坐标仍由 `SendInput` 执行。若程序目录没有 `interception.dll`，选项显示“未安装”，播放会在注入任何输入之前失败。驱动部署、授权和受保护游戏限制见 [鼠标回放兼容后端](raw-input-replay.md)。

点击播放时使用 Dashboard 最近记住的外部窗口；使用快捷键时通常就是当前游戏窗口。目标失焦、进程退出、停止快捷键、程序关闭或 `Ctrl+Alt+F12` 都会中止回放并执行 `release_all`。录制与回放互斥，所以播放/停止播放快捷键也不会进入训练轨迹。

## 物理输入与诊断输入

Dashboard 打开后会立即监视物理 Raw Input，是否正在录制不会影响界面预览。

“合成输入诊断（游戏录制请关闭）”未选中时，JSONL 只保留物理键鼠示范，并且程序不会安装全局低级键盘/鼠标 Hook。选中后，只在这一次录制期间临时安装 Hook，并保留带 inputd 专用标记的 `SendInput` 事件；停止录制后 Hook 会立即卸载。这些事件在 JSONL 中保持 `injected_tagged: true`，不会伪装成物理示范。

录制带反作弊或高频 Raw Input 的游戏时必须保持该选项关闭。生产录制只依赖 `WM_INPUT + RIDEV_INPUTSINK`，不注入、不挂游戏进程，也不尝试规避反作弊。Dashboard 必须与游戏处于相同完整性级别；发布版通过管理员清单保证这一点。

## 高频鼠标与训练数据完整性

界面显示与训练记录使用不同的数据路径：

- Raw Input 的每个原始事件都会进入无丢弃记录队列，按原始顺序和连续 `sequence` 写入 JSONL。
- 普通游戏录制不安装 `WH_MOUSE_LL`/`WH_KEYBOARD_LL`，避免全局 Hook 干扰游戏输入线程或触发反作弊兼容问题。
- 界面不会为每个鼠标包创建一条 WinForms 消息。它每 33ms 读取一次最新按键状态，并把该刷新周期内的鼠标 `dx/dy`、滚轮增量相加后显示。
- “显示合并”只影响动画刷新，不会合并、采样或删除 JSONL 中的训练事件。
- 写盘线程最多把 1024 条事件组成一批，使用 WriteThrough 文件流写入；输入消息线程不执行 JSON 序列化或磁盘 I/O。
- 点击“停止录制”后，程序会显示“正在落盘”，直到待写队列归零并完成最终 Flush。只有 `待写 0、失败 0` 且至少写入一条输入时状态才会变成“已完整保存”。完全没有事件的文件显示“无输入数据”，不会冒充可训练录制。

训练时只使用界面明确显示“已完整保存”的文件。如果磁盘已满、权限丢失或发生 I/O 错误，界面会显示“写入异常”并标记该文件不可直接用于训练，不会静默报告成功。

高轮询率录制建议使用空间充足的本地 SSD，不要直接写入网络盘或实时云同步目录。JSONL 保留每个原始事件，8000 Hz 鼠标会产生较大的数据量，这是保证事件不被静默丢弃的必要代价。

固定帧率生成器不会直接抽样删除事件：它累加帧内全部鼠标/滚轮增量，并在 `transitions` 中保留短按、短点击及其源序列号。完整格式和训练前校验方法见 [固定帧率训练数据](training-data.md)。

服务输入默认处于 Disarm 状态。注入测试必须绑定目标窗口并显式 Arm；焦点丢失、租约到期、断连、关闭或 `Ctrl+Alt+F12` 都会触发 `release_all`。
