# 相対マウス再生バックエンド

[简体中文](raw-input-replay.md) | [English](raw-input-replay.en.md) | [日本語](raw-input-replay.ja.md)

## デスクトップポインターは動くのにゲーム視点が動かない理由

記録されたマウス `dx/dy` は物理 Raw Input count です。Windows の相対 `SendInput` はデスクトップポインターを動かし、通常の Raw Input ウィンドウでも正確に観測できますが、一部のゲームはこの合成相対経路をカメラ操作に使いません。

そのため Dashboard の既定再生では相対移動だけ Win32 `mouse_event` を使い、同じ符号付き count、相対タイミング、held 状態を保持します。実際の互換性はオフラインまたは明示的に許可された対象で確認してください。

プレイヤーは held 状態が同じで総間隔が 2 ms 以下の高ポーリングマウスパケットを注入時に結合できます。各元イベントの符号付き `dx/dy/wheel` 合計を厳密に保持し、個別の `±1` count が Windows のポインター速度で丸められる問題を防ぎます。ただしゲーム側の合成入力受け入れ方針は変更できません。

## Dashboard のモード

- **カーネルマウス互換を選択しない（既定）：** 相対移動は `WindowsLegacyMouseReplayBackend`、その他はイベントタグなしの `WindowsSendInputBackend` が担当します。推奨のドライバー不要経路です。
- **カーネルマウス互換を選択：** 明示的な互換試験として、相対移動、マウスボタン、ホイールを `WindowsInterceptionInputBackend` が担当します。Runtime、ドライバー、マウスデバイス、driver report のいずれかがなければ、入力前に明確に失敗します。

どのバックエンドも専用 `InputScheduler` で直列化されます。再生停止、フォーカス喪失、対象終了、アプリ終了、緊急停止ではキューを消去して `release_all` を実行します。

## Interception 導入境界

リポジトリが提供するのはアダプターだけで、第三者 `Interception` カーネルドライバーと DLL を同梱も自動インストールもしません。有効化する前に：

1. 第三者マウスクラスフィルタードライバーの導入をユーザーが明示的に承認する；
2. 管理者権限で導入し、必要なら再起動する；
3. 対応する x64 `interception.dll` を `inputd-dashboard.exe` と同じ場所に置く；
4. Dashboard を再起動し、「未インストール」と表示されないことを確認する。

`DefaultDllImportSearchPaths(ApplicationDirectory)` により DLL はアプリディレクトリからだけ読み込まれ、現在のディレクトリや `PATH` は検索しません。利用不能な場合に、ゲーム再生の偽成功を返す経路へフォールバックしません。

公開 Interception は古く、商用と非商用のライセンス条件が異なります。ソース、配布物、ライセンスを自分で確認してください。保護されたオンラインゲームではフィルタードライバーを禁止したり、アンチチートが阻止したりする場合があります。inputd はアンチチート回避を提供しません。許可された環境だけで使ってください。

## 長期運用案

長期的には inputd 専用の署名済み Windows Virtual HID Framework (VHF) ドライバーが候補です。VHF HID source はカーネルモードで動作し、WDK、ドライバー署名、インストーラー、再起動試験が必要です。第三者依存を減らせますが、明示的な許可なしにシステムを変更できる通常のユーザーモード更新ではありません。
